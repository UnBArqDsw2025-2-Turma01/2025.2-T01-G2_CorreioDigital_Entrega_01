# Baseline

## Introdução

A baseline estabelece a versão aprovada dos requisitos funcionais e não funcionais que servirão como referência oficial para o desenvolvimento do sistema. A partir deste documento, qualquer modificação nos requisitos deverá ser submetida ao processo de controle de mudanças, garantindo rastreabilidade, consistência e alinhamento entre a equipe de desenvolvimento e os stakeholders.

## Objetivo/Metodologia

O objetivo desta baseline é consolidar e formalizar os requisitos elicitados durante a fase inicial do projeto CorreioDigital, a partir da entrevista com uma usuária representativa. 

A baseline foi construída com base no processo de engenharia de requisitos, seguindo as etapas:

1. Elicitação – Realização de uma entrevista estruturada com uma usuária em potencial do aplicativo, explorando suas motivações, dificuldades, expectativas e sugestões.

2. Análise – Interpretação das respostas para identificar requisitos explícitos e implícitos, tanto funcionais quanto não funcionais.

3. Documentação – Organização dos requisitos em tabelas categorizadas, garantindo clareza e rastreabilidade.

4. Validação – Revisão dos requisitos por membros da equipe para verificar consistência, completude e alinhamento com as necessidades do usuário.

5. Baseline – Definição da versão aprovada (v1.0), registrada neste documento, que servirá como contrato inicial para guiar o desenvolvimento do sistema.

## Baseline do Projeto CorreioDigital (v1.0)

A baseline contempla os requisitos elicitados por meio de uma entrevista realizada com uma potencial usuária, descritos no documento de [Entrevista](https://github.com/UnBArqDsw2025-2-Turma01/2025.2-T01-G2_CorreioDigital_Entrega_01/tree/main/docs/Base/1.1%20Design%20Sprint/1.6.2Entrevista.md).

### 1. Escopo da Baseline

- **Incluso:**  
  - Desenvolvimento de um site/app de chat entre usuários para aprendizado de idiomas.  
  - Funcionalidades: chat em texto/voz, matching inteligente, gamificação, histórico de conversas.  
  - Requisitos funcionais e não funcionais conforme documento de elicitação (Entrevista, Introspecção).  
  - Integração com sistemas externos (ex.: redes sociais de terceiros, API de tradução premium). 

- **Excluso (fora do escopo inicial):**  
  - Tradução automática instantânea.  
  - Suporte a chamadas de vídeo.

**Congelamento**

- Após a aprovação, a baseline foi congelada, e quaisquer alterações só podem ser realizadas via processo de controle de mudanças.

**Controle de Mudanças**

- ***Solicitação:*** qualquer membro do time ou stakeholder pode solicitar alteração (RFC – Request for Change).

- ***Análise:*** equipe avalia impacto, custo e risco da mudança.

- ***Aprovação/Rejeição:*** mudanças relevantes são aprovadas em conjunto com stakeholders.

- ***Versionamento:*** a baseline é atualizada para uma nova versão (ex.: 1.1, 1.2).
